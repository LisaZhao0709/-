# ESP32 双摇杆纯模拟手册（`Remote control/wifi.py`）

本文档说明如何在 ESP32 上运行双摇杆四轮小车纯模拟系统：仅输出状态，不访问 I2C 电机硬件。

## 1. 功能概览

`wifi.py` 当前版本实现：
- ESP32 建立 WiFi（默认 AP 热点）
- 手机浏览器访问控制页
- 双摇杆控制四轮速度计算（LF/LR/RF/RR）
- 底部实时状态栏 + 四轮方向与数值条
- 终端 20Hz（50ms）单行状态输出
- 断信号超时强停
- 纯模拟模式：不初始化 I2C/PCA9685，不会因硬件缺失报错

## 2. 默认参数

- WiFi AP：
  - `ssid = ESP32D_CAR`
  - `password = 12345678`
  - `port = 80`
- 控制参数：
  - 原始值范围 `0~4095`，中心 `2048`
  - 死区 `50`
  - 最大输出 `255 * 0.8 = 204`
  - 差速补偿阈值 `30%`，快侧回调 `10%`
  - 后轮跟随系数 `0.95`
  - 电刹强度 `5%`，持续 `100ms`
  - 快速回中判定：`>20%` 且 `200ms` 内回中
  - 断信号超时停车：`1500ms`

## 3. 启动步骤

1. 将 `wifi.py` 上传到 ESP32 MicroPython 文件系统。
2. 在串口 REPL 运行 `wifi.py`。
3. 记录串口输出的 IP（AP 模式一般是 `192.168.4.1`）。
4. 手机连接热点 `ESP32D_CAR`。
5. 打开浏览器访问 `http://<ESP32_IP>/`。
6. 进入页面后直接拖动双摇杆体验。

## 4. 页面与交互说明

- 左摇杆：控制左侧轮组（LF/LR）
- 右摇杆：控制右侧轮组（RF/RR）
- 松手后摇杆自动回中
- 页面上可切换刹车模式：
  - 关闭：滑行（默认）
  - 开启：电刹
- 底部状态行显示格式：
  - `LF:+180 LR:-120 RF:+255 RR:+200 | 左杆Y:+70% 右杆Y:+100% | 模式:滑行`

## 5. 算法逻辑（已实现）

1. 死区过滤：偏移量绝对值 < 50 归零
2. 指数映射：`sign(x) * (|x|%)^2`
3. 最大速度限幅：80%
4. 左右轮独立目标速度：由左右摇杆 Y 轴计算
5. 差速补偿：左右差值超过 30% 时，快侧降速 10%
6. 原地旋转修正：左右异号且幅值接近时强制等幅
7. 前后轮同步补偿：后轮 = 前轮 * 0.95
8. 快速回中刹车：支持滑行/电刹两模式
9. 最高权限强停：双摇杆都在死区时四轮强制停转

## 6. 终端输出要求

- 刷新频率：20Hz（每 50ms）
- 输出方式：覆盖同一行（`\r`）
- 输出内容：四轮速度、左右摇杆 Y%、刹车模式

## 7. 自检测试

`wifi.py` 启动时会自动执行 `run_all_tests()`，打印：
- `[SUCCESS]` / `[FAILED]`
- 耗时（ms）
- 输入/输出

覆盖测试包括：
- 死区
- 指数映射
- 限幅
- 差速补偿
- 原地旋转
- 前后轮补偿
- 刹车逻辑
- 双杆中心强停
- 超时强停

## 8. 常见问题

### 8.1 手机打不开控制页
- 确认手机已连接 `ESP32D_CAR`。
- 确认访问地址正确（默认 `http://192.168.4.1/`）。
- 确认 ESP32 已正常运行 `wifi.py`。

### 8.2 页面有显示但状态不更新
- 检查浏览器是否阻止本地请求。
- 刷新页面后重试。
- 查看串口是否有请求处理异常日志。

### 8.3 串口输出卡顿
- 可把前端发送频率从 50ms 调为 80~100ms。
- 尽量关闭页面中其他占用网络的应用。

### 8.4 为什么不驱动电机
- 本版本是纯模拟体验版，目标是稳定和安全。
- 不访问 I2C，避免无驱动板时出现 `ENODEV` 报错。
